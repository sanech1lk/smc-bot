# Запуск на своём сервере: от покупки до работающего сайта

Пошагово, без предположений о том, что вы уже это делали. Весь путь —
примерно час, из которых половина ожидание.

Что понадобится: домен (~50–80 zł в год), VPS (примерно 5–7 € в месяц) и
почтовый ящик для отправки писем. Итого около 10 € в месяц.

---

## Шаг 1. Купить домен

Домен нужен обязательно: без него не выпустить сертификат HTTPS, а без HTTPS
браузер запретит геолокацию, push-уведомления и офлайн-режим — половина
приложения работать не будет.

Где взять (любой подойдёт):

- **[OVH](https://www.ovhcloud.com/pl/domains/)** — крупный европейский регистратор
- **[nazwa.pl](https://nazwa.pl)**, **[cyberfolks.pl](https://cyberfolks.pl)** — польские, интерфейс по-польски
- **[Cloudflare Registrar](https://www.cloudflare.com/products/registrar/)** — продаёт по себестоимости, но нужен аккаунт Cloudflare

Возьмите что-то короткое: `budchat.pl`, `budchat.app`. Домен `.pl` стоит
дешевле для польского рынка и вызывает больше доверия у местных клиентов.

## Шаг 2. Купить сервер

Нужен **VPS** — виртуальный сервер, где вы сами ставите софт. Не «хостинг для
сайтов» с панелью управления: там нельзя запустить Docker.

**Минимум:** 2 ГБ оперативной памяти, 2 ядра, 40 ГБ диска. Меньше 2 ГБ не
берите — сборка приложения не поместится.

Где брать:

| Провайдер | Где серверы | Комментарий |
| --- | --- | --- |
| **[Hetzner](https://www.hetzner.com/cloud)** | Германия, Финляндия | Лучшее соотношение цены и качества в ЕС. Тариф CX22 (2 ядра / 4 ГБ) — ориентировочно 4–6 € в месяц; в 2026 цены менялись, смотрите актуальные на сайте |
| **[mikr.us](https://mikr.us)** | Польша | Маленький польский провайдер, дёшево, интерфейс по-польски |
| **[OVH](https://www.ovhcloud.com/pl/vps/)** | Польша, Франция | Есть дата-центр в Варшаве |
| **[Contabo](https://contabo.com)** | Германия | Дёшево за много ресурсов, но медленнее остальных |

> **Про «сервер должен быть в Польше».** Для GDPR достаточно любой страны
> Европейской экономической зоны — Германия подходит так же, как Польша. Это
> сильно расширяет выбор. Если возьмёте не польский дата-центр, поправьте
> строку про хостинг в политике конфиденциальности
> (`src/app/legal/privacy/page.tsx`).

При заказе выбирайте:

- **Образ (image):** Ubuntu 24.04
- **Локация:** любая в ЕС, ближе к клиентам — Nuremberg, Falkenstein, Warszawa
- **SSH-ключ:** если есть — добавьте, это удобнее и безопаснее пароля. Если
  нет, провайдер пришлёт root-пароль на почту

После оплаты вы получите **IP-адрес** вида `95.216.xx.xx`. Он понадобится
дальше.

## Шаг 3. Направить домен на сервер

В панели регистратора домена найдите управление DNS и добавьте две записи:

| Тип | Имя | Значение |
| --- | --- | --- |
| A | `@` | IP вашего сервера |
| A | `www` | IP вашего сервера |

Изменения расходятся по интернету от нескольких минут до пары часов.
Проверить, что уже сработало:

```bash
ping budchat.pl
```

Если в ответе видно ваш IP — можно идти дальше. Пока показывает старое,
подождите и повторите.

## Шаг 4. Зайти на сервер и подготовить его

С вашего компьютера (PowerShell на Windows, Terminal на Mac/Linux):

```bash
ssh root@95.216.xx.xx
```

Первый раз спросит про подлинность ключа — ответьте `yes`.

Дальше команды выполняются **на сервере**. Обновляем систему и ставим Docker:

```bash
apt update && apt upgrade -y
curl -fsSL https://get.docker.com | sh
```

Проверяем, что встало:

```bash
docker --version
docker compose version
```

Ставим firewall — наружу нужны только SSH и веб:

```bash
apt install -y ufw
ufw allow OpenSSH
ufw allow 80
ufw allow 443
ufw --force enable
```

## Шаг 5. Настроить почту

Приложение отправляет письма: подтверждение адреса, восстановление пароля,
приглашения. Без почты эти сценарии не работают.

**Gmail** (быстро, годится для пилота):

1. Создайте отдельный ящик, например `budchat.app@gmail.com`
2. Включите двухфакторную аутентификацию — без неё следующий шаг недоступен
3. Зайдите в [пароли приложений](https://myaccount.google.com/apppasswords) и
   создайте пароль для «Mail». Это 16 символов — обычный пароль от ящика в
   SMTP не работает

Лимит бесплатного Gmail — около 500 писем в сутки, и письма от него чаще
попадают в спам. Для боевого запуска лучше **[Brevo](https://brevo.com)**,
**[Postmark](https://postmarkapp.com)** или **[Resend](https://resend.com)**: у
всех есть бесплатный тариф на первые письма, и они подписывают договор об
обработке данных, чего с обычным Gmail не сделать.

## Шаг 6. Развернуть приложение

На сервере:

```bash
git clone https://github.com/sanech1lk/smc-bot.git
cd smc-bot/budchat
git checkout claude/budchat-pwa-messenger-wezn1w
cp .env.example .env
nano .env
```

Открылся редактор. Заполните (стрелками двигайтесь, просто печатайте):

```bash
DATABASE_URL="postgresql://budchat:budchat@postgres:5432/budchat?schema=public"

# Ваш домен — от него зависят ссылки в письмах и защищённость сессий
NEXTAUTH_URL="https://budchat.pl"
APP_DOMAIN="budchat.pl"
ACME_EMAIL="вашапочта@gmail.com"

# Ключ подписи сессий. Сгенерируйте своим: см. команду ниже
NEXTAUTH_SECRET="сюда_вставить_сгенерированное"

NODE_ENV=production
PORT=3000

# Почта из шага 5
SMTP_HOST="smtp.gmail.com"
SMTP_PORT="587"
SMTP_USER="budchat.app@gmail.com"
SMTP_PASSWORD="пароль_приложения_16_символов"
SMTP_FROM="BudChat <budchat.app@gmail.com>"
```

Сохранить в `nano`: `Ctrl+O`, `Enter`, затем `Ctrl+X`.

Сгенерировать ключ сессий и вписать его автоматически:

```bash
sed -i "s|^NEXTAUTH_SECRET=.*|NEXTAUTH_SECRET=\"$(openssl rand -base64 32)\"|" .env
```

> Приложение **не запустится**, если оставить шаблонный ключ из
> `.env.example`: этим ключом подписываются сессии, и с публично известным
> значением чужой вход подделывается. Проверка живёт в `env-guard.js`.

Запускаем:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Первая сборка идёт 5–10 минут. Следим за логами:

```bash
docker compose logs -f
```

Когда увидите `BudChat ready` и Caddy перестанет ругаться на сертификат —
открывайте `https://budchat.pl`. Сертификат выпускается автоматически, ничего
делать не нужно.

Выйти из логов: `Ctrl+C` (контейнеры продолжат работать).

## Шаг 7. Создать первого пользователя

Просто зарегистрируйтесь через сайт — первый аккаунт ничем не отличается от
остальных, дальше вы создаёте объект и приглашаете людей.

Если хотите посмотреть на демо-данные (объект, этапы, смета, чек-лист):

```bash
docker compose exec app npx tsx prisma/seed.ts
```

Демо-аккаунты: `prorab@budchat.dev` / `master@budchat.dev` /
`client@budchat.dev`, пароль `password123`. **Перед показом реальным людям
удалите их** — пароль известен всем, кто читал репозиторий.

## Шаг 8. Включить бэкапы

Обязательный шаг, а не необязательный: потеря сервера без копии — это потеря
всех фотоотчётов, смет и подписей приёмки.

```bash
crontab -e
```

Добавьте строку (копия каждую ночь в 3:00):

```
0 3 * * * cd /root/smc-bot/budchat && ./scripts/backup.sh >> /var/log/budchat-backup.log 2>&1
```

Копии складываются в `backups/`, старше 30 дней удаляются автоматически.

**Копия на том же сервере не спасает от потери сервера.** Раз в неделю
забирайте её к себе:

```bash
scp -r root@95.216.xx.xx:/root/smc-bot/budchat/backups ./
```

И хотя бы раз проверьте, что восстановление работает — на тестовом сервере,
не на боевом:

```bash
./scripts/restore.sh ./backups/2026-08-15_03-00-00
```

## Дальше: что делать по ходу

**Обновить приложение до новой версии:**

```bash
cd /root/smc-bot/budchat
git pull
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
```

Миграции базы применяются сами при старте контейнера.

**Посмотреть, живо ли всё:**

```bash
curl https://budchat.pl/api/health     # {"status":"ok"}
docker compose ps                      # состояние контейнеров
docker compose logs --tail=100 app     # последние записи
```

**Включить push-уведомления** (по желанию):

```bash
npx web-push generate-vapid-keys
```

Полученные ключи впишите в `.env` как `VAPID_PUBLIC_KEY` и
`VAPID_PRIVATE_KEY`, затем перезапустите контейнеры.

## Если что-то не работает

**Сайт не открывается, браузер пишет про сертификат.** Скорее всего DNS ещё
не разошёлся или указывает не туда. Проверьте `ping budchat.pl` — должен
отвечать ваш IP. Caddy выпустит сертификат сам, как только домен доедет.

**Контейнер `app` перезапускается по кругу.** Смотрите причину:
`docker compose logs app`. Чаще всего это проверка окружения — она пишет
прямым текстом, какой переменной не хватает.

**Письма не приходят.** Проверьте, что в `SMTP_PASSWORD` именно пароль
приложения (16 символов), а не пароль от ящика. Если SMTP не настроен вовсе,
приложение не падает — текст письма печатается в логи, ссылку можно взять
оттуда: `docker compose logs app | grep verify-email`.

**Кончилось место на диске.** Посмотрите, что занимает:
`docker system df`. Старые образы чистятся командой
`docker system prune -a` (осторожно: удалит неиспользуемые образы, но не
тома с данными).
